### Requirement: Build unsigned auth token request XML

The system SHALL provide a public `buildUnsignedAuthTokenRequestXml(options)` function that generates a valid KSeF auth token request XML document without a signature. The function SHALL accept an options object with `challenge` (string), `contextIdentifier` (ContextIdentifier with type and value), and optional `subjectIdentifierType` (defaults to `'certificateSubject'`). The XML SHALL conform to the `http://ksef.mf.gov.pl/auth/token/2.1` namespace schema.

#### Scenario: Build XML with Nip context identifier
- **WHEN** `buildUnsignedAuthTokenRequestXml` is called with `challenge: "abc123"`, `contextIdentifier: { type: 'Nip', value: '1234567890' }`
- **THEN** the returned XML SHALL contain `<Nip>1234567890</Nip>` inside `<ContextIdentifier>`, the challenge value in `<Challenge>`, `<SubjectIdentifierType>certificateSubject</SubjectIdentifierType>`, and the `http://ksef.mf.gov.pl/auth/token/2.1` namespace on the root element

#### Scenario: Build XML with InternalId context identifier
- **WHEN** `buildUnsignedAuthTokenRequestXml` is called with `contextIdentifier: { type: 'InternalId', value: 'INT-001' }`
- **THEN** the returned XML SHALL contain `<InternalId>INT-001</InternalId>` inside `<ContextIdentifier>`

#### Scenario: Build XML with NipVatUe context identifier
- **WHEN** `buildUnsignedAuthTokenRequestXml` is called with `contextIdentifier: { type: 'NipVatUe', value: 'PL1234567890' }`
- **THEN** the returned XML SHALL contain `<NipVatUe>PL1234567890</NipVatUe>` inside `<ContextIdentifier>`

#### Scenario: Build XML with PeppolId context identifier
- **WHEN** `buildUnsignedAuthTokenRequestXml` is called with `contextIdentifier: { type: 'PeppolId', value: '0088:1234567890' }`
- **THEN** the returned XML SHALL contain `<PeppolId>0088:1234567890</PeppolId>` inside `<ContextIdentifier>`

#### Scenario: Custom subject identifier type
- **WHEN** `buildUnsignedAuthTokenRequestXml` is called with `subjectIdentifierType: 'certificateFingerprint'`
- **THEN** the returned XML SHALL contain `<SubjectIdentifierType>certificateFingerprint</SubjectIdentifierType>`

#### Scenario: XML-unsafe characters in values are escaped
- **WHEN** `buildUnsignedAuthTokenRequestXml` is called with a challenge containing `<`, `>`, `&`, `"`, or `'`
- **THEN** the returned XML SHALL escape those characters to their XML entity equivalents

#### Scenario: XML includes declaration and is well-formed
- **WHEN** `buildUnsignedAuthTokenRequestXml` is called with any valid options
- **THEN** the returned XML SHALL start with `<?xml version="1.0" encoding="utf-8"?>` and SHALL be parseable by a standard XML parser

### Requirement: Authenticate with externally-signed XML via workflow

The system SHALL provide an `authenticateWithExternalSignature(client, options)` workflow function that orchestrates the full external signing authentication flow. The function SHALL: (1) get a challenge from KSeF, (2) build the unsigned XML, (3) invoke the caller's `signXml` callback with the unsigned XML, (4) submit the signed XML via `submitXadesAuthRequest`, (5) poll for auth completion, and (6) redeem access and refresh tokens. The function SHALL set the tokens on the client's auth manager upon success.

#### Scenario: Successful external signing authentication
- **WHEN** `authenticateWithExternalSignature` is called with a valid `signXml` callback that returns signed XML
- **THEN** the function SHALL return an `AuthResult` with `accessToken`, `accessTokenValidUntil`, `refreshToken`, and `refreshTokenValidUntil`, and the client's auth manager SHALL have both tokens set

#### Scenario: signXml callback receives unsigned XML
- **WHEN** the workflow executes and calls the `signXml` callback
- **THEN** the callback SHALL receive the unsigned XML string generated by `buildUnsignedAuthTokenRequestXml` using the provided `contextIdentifier`

#### Scenario: signXml callback can be async
- **WHEN** `signXml` returns a Promise that resolves to signed XML
- **THEN** the workflow SHALL await the promise and proceed with the resolved value

#### Scenario: signXml callback error propagates
- **WHEN** the `signXml` callback throws an error or returns a rejected promise
- **THEN** the workflow SHALL propagate the error to the caller without submitting to KSeF

#### Scenario: Polling and token options are forwarded
- **WHEN** `authenticateWithExternalSignature` is called with `verifyCertificateChain`, `enforceXadesCompliance`, and `pollOptions`
- **THEN** these options SHALL be forwarded to `submitXadesAuthRequest` and `pollUntil` respectively

### Requirement: Backward-compatible auth token XML builder

The existing `buildAuthTokenRequestXml(challenge, nip, subjectIdentifierType)` function SHALL remain available with the same signature and behavior. It SHALL delegate to `buildUnsignedAuthTokenRequestXml` internally, mapping its `nip` parameter to `contextIdentifier: { type: 'Nip', value: nip }`.

#### Scenario: Existing callers are unaffected
- **WHEN** `buildAuthTokenRequestXml("challenge", "1234567890")` is called
- **THEN** the output SHALL be identical to the current implementation's output

#### Scenario: Existing callers with custom subject identifier type
- **WHEN** `buildAuthTokenRequestXml("challenge", "1234567890", "certificateFingerprint")` is called
- **THEN** the output SHALL contain `<SubjectIdentifierType>certificateFingerprint</SubjectIdentifierType>`

### Requirement: CLI external signing command

The CLI SHALL provide a `ksef auth login-external` command with two phases. The generate phase (`--generate`) SHALL get a challenge, build unsigned XML, and output it to stdout or a file specified by `--output`. The submit phase (`--submit`) SHALL read signed XML from stdin or a file specified by `--input`, submit it, poll for completion, and store the session credentials. Both phases SHALL accept `--nip` (required), `--env` (environment), and `--context-type` (defaults to `Nip`).

#### Scenario: Generate unsigned XML to stdout
- **WHEN** `ksef auth login-external --generate --nip 1234567890 --env test` is executed
- **THEN** the command SHALL print the unsigned auth request XML to stdout and print the reference metadata (challenge, expiry hint) to stderr

#### Scenario: Generate unsigned XML to file
- **WHEN** `ksef auth login-external --generate --nip 1234567890 --output unsigned.xml` is executed
- **THEN** the command SHALL write the unsigned XML to `unsigned.xml` and print confirmation to stderr

#### Scenario: Submit signed XML from file
- **WHEN** `ksef auth login-external --submit --nip 1234567890 --input signed.xml` is executed
- **THEN** the command SHALL read `signed.xml`, submit it to KSeF, poll for auth completion, and store the session credentials

#### Scenario: Submit signed XML from stdin
- **WHEN** signed XML is piped to `ksef auth login-external --submit --nip 1234567890`
- **THEN** the command SHALL read signed XML from stdin and proceed with submission

#### Scenario: Non-Nip context type
- **WHEN** `ksef auth login-external --generate --nip PL1234567890 --context-type NipVatUe` is executed
- **THEN** the generated XML SHALL use `<NipVatUe>` as the context identifier element

### Requirement: Public API exports

The package entry point SHALL export `buildUnsignedAuthTokenRequestXml`, `AuthTokenRequestXmlOptions`, `authenticateWithExternalSignature`, and `ExternalSignatureAuthOptions` so they are available to library consumers.

#### Scenario: Import from package
- **WHEN** a consumer writes `import { buildUnsignedAuthTokenRequestXml } from 'ksef-client-ts'`
- **THEN** the import SHALL resolve successfully

#### Scenario: Import types from package
- **WHEN** a consumer writes `import type { AuthTokenRequestXmlOptions, ExternalSignatureAuthOptions } from 'ksef-client-ts'`
- **THEN** the type imports SHALL resolve successfully
